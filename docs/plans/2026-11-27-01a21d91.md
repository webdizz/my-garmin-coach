## Implementation

1. Kanboard: add dependency GC-25 → GC-28. Implement GC-28 first as its own change (not part of this plan).
2. Server loader `getYouState(db)`: combines check-in, active niggles, active goal, training slots, key status (from GC-28 repos) with `getSyncStatus` (existing, `src/sync/status.ts`). Returns plain serialisable data.

Use route handlers or server actions guarded like `/api/sync` (`requireSession`, cross-site Origin check, input validation). Read the Next.js docs in `node_modules/next/dist/docs/` first (AGENTS.md warns of breaking changes).
4. `/you` page (server component, behind the existing proxy gate) with sections: Current state, Data (freshness + "Refresh now" calling `POST /api/sync`, polling `GET /api/sync`), Training slots (read-only), Garmin key row, Security (reuse `LockControls`; show "Auto-lock after 5 min" text), footer note "Informational, not medical advice".

6. Style with existing tokens in `design-tokens.css`; follow the mockup `#you` section for layout (cards, pills, list rows). 430px max width, safe-area padding.
7. Tests (synthetic data only): loader, mutation validation and auth rejection, component render states (no sync yet, sync error, key missing/expiring, no niggles). Update `docs/changes.md` with a GC-25 entry.
8. Run `npm run verify` in full and report.

### Risks

- GC-28 is not done. Without it this ticket would invent its own tables. Mitigation: sequence GC-28 first.
- Architecture rules: a new `you` module must pass dependency-cruiser (`sync` and `auth` must not import each other; `garmin`/`db` must not import `app`). The loader should live where it only imports `db` and `sync`.
- Client components must not import `src/db`, `src/garmin` or `src/auth` (except `@/auth/client`). Pass data as props.
- Mutation endpoints handle health data: validate enums and lengths, never log payloads.
- Mutation testing (Stryker, break at 74%) is slow and may need extra tests for validation branches.
- Time zone: slot and sync times are UTC in GC-9; display in local time only, and do not show raw UTC as if local.
