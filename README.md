# GarminConnect

A small personal web app to explore my own Garmin Connect data: charts, training and
fitness trends, and an AI assistant for questions about training, fitness and health.

> Status: **Early development.** Next.js scaffold, database foundation (async SQLite + Drizzle) and the server-only Garmin client are in place.
> See [`docs/`](docs/) for architecture, decisions, and the UI prototype in [`docs/mockup/`](docs/mockup/index.html).

## Goals

1. Import and store my Garmin data (sleep, HRV, resting HR, stress, body battery, weight,
   activities including FIT files).
2. Show charts for trends and training load.
3. Provide an agentic assistant that answers questions grounded in my data and shows which
   numbers it used.
4. Usable on iPhone, as an installed PWA.
5. Private: single-user login. The Garmin key never reaches the browser.

## Main screens

Login, Today, Plan, Trends, Coach (weekly threads), You. Details in [`docs/ui-mockup.md`](docs/ui-mockup.md).

## Tech stack

- **Frontend & API:** Next.js 16 (App Router, TypeScript)
- **Database:** async SQLite (`@libsql/client`) + Drizzle ORM
- **IDs:** ULID (26 chars, sortable)
- **Data source:** Garmin Connect Developer Program – Personal API (personal API key, pull-only)
- **Agent layer:** TBD (see [`docs/decisions.md`](docs/decisions.md))
- **UI framework:** React 19 + Tailwind CSS

## Quick start

### Local setup

```bash
# Install dependencies
npm install

# Dev server starts on http://localhost:3344
npm run dev

# Type checking and linting
npm run typecheck
npm run lint

# Tests
npm run test           # Watch mode
npm run test:ci        # Single run with coverage
npm run test:coverage  # Full coverage report

# Database
npm run db:generate    # Generate migrations
npm run db:migrate     # Apply migrations

# Full verification suite
npm run verify         # Runs: lint + typecheck + test:ci
```

### Environment

Create `.env.local` for local development:

```bash
# Optional; default is file:./data/app.db (local SQLite)
DATABASE_URL=file:./data/app.db

# Garmin API credentials (see docs/garmin-api.md)
GARMIN_API_KEY=...
```

## Privacy & security

- Health data stays on your machine or private host. Do not commit personal exports (`.csv`) or `.env`.
- `/fixtures/` and `/data/` are gitignored.
- Tests use synthetic data only.

## Git workflow

Pre-commit hooks (Husky) run automatically on each commit:

- ESLint (auto-fix)
- TypeScript type checking
- Jest tests (bail on first failure)

To bypass hooks (not recommended):

```bash
git commit --no-verify
```

## Recent work

### GC-8: Garmin client (token exchange and typed fetchers)

- `src/garmin/`: server-only client for the Personal API. The API key is exchanged for a 24 h Bearer token, cached and re-requested on 401.
- Typed fetchers take `Date` (local calendar day) and return promises: HRV, sleep, resting HR, HR zones, weight, body battery, stress, daily summary, fitness age, VO2max, activities.
- Every request is limited to `https://personal.connectapi.garmin.com` over HTTPS. Errors carry status and path only.
- 22 offline tests (stub fetch, synthetic data).

### GC-6: Database Foundation (async SQLite + Drizzle)

- Added `src/db/` module with async `@libsql/client` driver
- Drizzle ORM schema (dialect-agnostic, migration path to Postgres)
- Three base tables: `raw_json` (Garmin responses), `sync_run` (sync history), `settings` (typed key/value)
- ULID monotonic IDs
- Typed repository layer (rawJsonRepo, syncRunRepo, settingsRepo)
- In-memory test helper (`createTestDb()`)
- 6 synthetic-data tests
- Dev server on port 3344
- Drizzle migrations in `drizzle/` (generated via `npm run db:generate`)
